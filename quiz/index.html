Design a reliable movie-intelligence pipeline

A team gives you a TMDB API key and asks for a pipeline that fetches movies, cleans and stores them, trains a high-engagement classifier, creates content-based recommendations, and groups similar movies. It must handle missing records, API limits, unseen categories, and repeat runs without silently corrupting the catalog.

In your own words, outline the stages in order. Include how you would validate the model, keep preprocessing consistent, persist reusable artifacts, and check whether the pipeline produced trustworthy output.

Self-check opened. Compare your answer with the checklist below; this is an architecture exercise, so there is no single exact wording.
Reveal the scenario review checklist
  1. Keep the API key in environment configuration, not source code; set timeouts, handle 404s, and retry or back off on rate limits such as HTTP 429.
  2. Validate response shape and required fields, normalize JSON into tabular rows, deduplicate by stable movie ID, parse dates, and handle missing or implausible values deliberately.
  3. Persist cleaned records in MongoDB with a clear idempotent upsert/replacement strategy; verify counts and representative documents after writing.
  4. Define the engagement target precisely. Derive any threshold from training data only, then make a stratified train/test split to protect class proportions and reduce leakage.
  5. Put numeric imputation/scaling and categorical imputation/one-hot encoding inside a ColumnTransformer and model Pipeline; allow unseen categories at inference time.
  6. Use cross-validation and an appropriate search strategy for model selection; report multiple metrics (for example precision, recall, F1, ROC-AUC, and a confusion matrix) rather than accuracy alone.
  7. Fit TF-IDF on movie text, retain the row-to-movie mapping, use cosine similarity for ranked recommendations, and test empty/unmatched queries.
  8. Scale numeric fields and combine them thoughtfully with text vectors before K-means; choose/evaluate cluster counts with a measure such as silhouette score and inspect cluster profiles.
  9. Persist the fitted model, preprocessing pipeline, vectorizer, sparse matrix, and metadata with clear paths/versions. Reload each artifact and test a real prediction/query.
  10. Make reruns observable and safe: log counts and errors, avoid broad silent exception handling, verify output files/collections, and compare expected row counts or schema.
